# r6：性能优化、llama 调参和 Harness 快照更新（2026-10-02）

本地新配置默认上下文 131072、最大输出 65536；外部 API 模型仍由 API/使用者自行配置。llama 默认 Flash Attention=on、K/V 缓存=q8_0、batch=2048、ubatch=512。q8_0 具有量化精度取舍，调参页可改回 f16；不会擅自修改旧配置中已经保存的数值。

新增主程序侧栏“llama 启动调参”，可设置上下文、输出、线程、批大小、GPU 层数、CUDA 目录、Flash Attention 和 K/V 精度，支持保存并启动/重启。已加载模型仍使用启动时参数，保存不会自动重启；点击重启会中断当前本地推理，Harness 服务不停止。两个参数页面切换时读取已保存改动，不会把高级选项重置为默认值。

Harness 保留系统提示词与工具能力；关闭额外模型调用生成会话标题，保留普通标题回退。模型提供方、地址与参数仍由使用者在 Harness 内维护。

## 性能验证

在 RTX 5090、b11060、Huihui-Qwen3-VL-8B-Instruct-abliterated.Q8_0 和相同固定输入下，旧配置为上下文 196608 / f16 KV / 512/128 批大小，新配置为 131072 / q8_0 KV / 2048/512。单次对照结果：

| 测试 | 旧配置 | 新配置 |
|---|---:|---:|
| 短输入，固定生成 128 token | 93.8 token/s | 151.4 token/s |
| 约 9100 token 输入，固定生成 128 token | 26.3 token/s | 133.2 token/s |
| 同一长输入的首轮提示词处理 | 20.40 秒 | 0.77 秒 |
| 真实 Harness 四句话任务总耗时 | 13.78 秒 | 3.42 秒 |
| 真实 Harness 请求的后端解码速度 | 34.8 token/s | 139.5 token/s |
| CUDA KV 缓存 | 27648 MiB | 9792 MiB |

真实 Harness 使用自身系统提示词与工具 schema（约 5105 token），两次均正常退出；生成长度分别 50/52 token，因此总耗时不是固定 token 数的纯解码对比。结果只代表本机本次样本，不保证所有模型/长会话都达到该速度。证据：artifacts/performance-r6-verified/results.json 和两组 logs。

## Harness 更新与回滚

界面分别显示当前版本、官方最新版本、可选择的已备份版本。最新版本读取 https://github.com/deepseek-ai/deepseek-harness 的 GitHub Releases（包含预发布），按发布时间选择 dsh-v 发布，再核对官方 @deepseek-ai/dsh npm 精确版本与完整性；不把尚未发布的 master 源码当作安装包。

更新前完成当前 Harness 的文件快照和摘要校验，再下载、验证最新版，最后在固定路径覆盖切换。快照放在 components/deepseek-harness/snapshots，保留多个版本；旧版 backup 也可选择。回滚前保留当前版本快照，按所选备份恢复。用户配置、会话和模型不属于组件快照，不被覆盖。运行中的 Harness 必须先停止，llama 不受影响。

更新/回滚展示当前阶段、复制文件数与阶段百分比、活动进度条和每秒更新的耗时。下载尚无准确总量时显示活动进度而非虚假总体百分比。取消在切换提交前生效；短暂的提交阶段由事务日志保护。

新版本查询、更新前备份顺序、多快照保留、选择回滚、篡改拒绝、路径校验及旧事务恢复均有自动化检查。界面截图与验证记录：artifacts/smoke-20261002-091524/logs。实际网络测试已成功从 0.1.5-rc.3 更新到官方 0.2.0-rc.2，新版 Web 启动就绪，并成功选择旧快照回滚；证据在 artifacts/harness-r6-live/logs。79 项自动化检查通过。
